# restaurant-finder: 飲食店候補リストアップスキル

## 概要

ユーザーの条件に合う飲食店を、複数のグルメサイトを横断検索してリサーチし、ファクトチェック済みの詳細情報を構造化された形式で出力する。

## ワークフロー

### Step 1: 条件の確認と整理

ユーザーの入力から以下の条件を抽出する。明示されていない項目は検索結果から適切に判断する。

| 条件 | 例 |
|---|---|
| **エリア** | 渋谷駅 道玄坂周辺 |
| **ジャンル** | 居酒屋、イタリアン、中華、etc. |
| **人数** | 20〜30名 |
| **予算** | 3,000〜5,000円/人 |
| **スタイル** | カウンター / テーブル / 個室 / フロア貸切 |
| **時間帯** | 夜20:00〜23:00 |
| **その他** | 飲み放題付き、プロジェクター有り、深夜営業、etc. |

条件が曖昧な場合でも、合理的な範囲で検索を進める。エリアだけの指定でも十分に検索可能。

### Step 2: 複数サイト横断リサーチ

以下のグルメサイトをWebSearchで横断検索する。1つのサイトだけで完結せず、**必ず複数のソースから情報を収集**する。

**主要検索対象サイト:**
- ホットペッパーグルメ (hotpepper.jp)
- ぐるなび (gnavi.co.jp)
- 食べログ (tabelog.com)
- 一休.comレストラン (restaurant.ikyu.com)
- ヒトサラ (hitosara.com)
- OZmall (ozmall.co.jp/restaurant)
- Retty (retty.me)

**検索のコツ:**
- `site:hotpepper.jp 渋谷 居酒屋 貸切 30名` のようにサイト指定検索を活用
- 各サイトの絞り込みキーワード（「個室あり」「貸切OK」「飲み放題」等）を含める
- エリア名は「駅名＋周辺エリア名」の組み合わせで幅を持たせる
- 最低でも **8〜12店舗** の候補を集める
- 各店舗の詳細ページ（ホットペッパー等）をWebFetchで読み取り、営業時間・コース詳細・設備情報を正確に取得する。「要確認」や「営業時間：要確認」は品質不足なので、必ず具体的な時間を記載すること

### Step 3: ファクトチェック

収集した店舗について、以下を確認する。これがこのスキルの品質を決定づける重要なステップ。

1. **営業状況の確認**: 閉店・移転していないかをWebSearchで確認。「〇〇 閉店」で検索するのが効果的
2. **情報の照合**: 住所・最寄駅・予算・人数を複数サイトで突き合わせ、食い違いがあれば最新情報を採用
3. **URLの確認**: WebFetchで各URLが有効かチェック（404やリダイレクトを検出）
4. **閉店済み店舗の除外**: 確認できた閉店店舗はリストから除外し、補足に記載

### Step 4: 出力フォーマット

以下の構造で出力する。この形式は崩さないこと。

## 品質基準

出力が以下の基準を満たしているか自己チェックする。基準を満たさない場合は追加検索で補完する。

1. **店舗数**: 最低 **7店舗以上** がリストに含まれている
2. **URL**: 各店舗に **2つ以上の予約サイトURL** が付いている
3. **情報の具体性**: 予算・人数・住所・営業時間が具体的に記載されている。「要問合せ」「要確認」は最小限に留め、WebFetchで詳細ページから情報を取得して埋める
4. **予算順の一覧表**: 必ず含まれている
5. **用途別おすすめ**: 最低3カテゴリ以上で分類されている
6. **ファクトチェック**: 閉店済み店舗が含まれていない
7. **情報の鮮度**: 検索結果の情報が最新であることを確認済み
8. **営業時間の記載**: 全店舗について具体的な営業時間（例: 17:00〜翌5:00）が記載されている

## 注意事項

- 情報は検索時点のWeb掲載情報に基づく旨を必ず注記する
- 貸切の最低人数・空き状況は日程により変動するため、早めの電話確認を推奨する旨を記載する
- ユーザーが追加条件を出した場合は、既存リストを基に絞り込み・追加検索を行う
