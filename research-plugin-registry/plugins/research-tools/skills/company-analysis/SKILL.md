# 企業包括分析スキル

対象企業について12の分析次元から包括的に分析し、構造化レポートを出力する。
3つの並列エージェントで効率的に情報収集し、統合・品質チェック後にレポートを生成する。

## 実行ワークフロー

### Phase 1: 3並列エージェントによる情報収集

3つのAgentを**同時に**起動し、それぞれ担当する分析次元の情報を収集する。
各エージェントはWebSearchとWebFetchを駆使して最新情報を取得する。

#### Agent 1: 企業基盤情報（4次元）

担当: 企業概要 / MVV / 事業内容・プロダクト / 市場環境

**実行するWebSearchクエリ（最低6クエリ）:**
1. `{company} 企業概要 設立 従業員数 資本金`
2. `{company} ミッション ビジョン バリュー 企業理念`
3. `{company} サービス プロダクト 事業内容`
4. `{company} 市場規模 TAM 業界動向`
5. `{company} 沿革 歴史 成長`
6. `{company} プレスリリース 新サービス 2025 2026`

**収集する情報:**
- 正式社名、設立年、本社所在地、従業員数、資本金、上場区分
- ミッション・ビジョン・バリューの原文（公式サイトから正確に引用）
- 主要プロダクト/サービスの名称・概要・対象顧客
- 属する市場の規模（TAM/SAM/SOM可能な範囲で）、成長率、主要トレンド

#### Agent 2: 経営・財務・競争力（4次元）

担当: 財務状況 / 経営陣・組織 / 3C分析 / 強み・差別化

**実行するWebSearchクエリ（最低6クエリ）:**
1. `{company} 売上 利益 業績 決算 IR`
2. `{company} 資金調達 シリーズ 評価額` （未上場の場合）
3. `{company} 代表取締役 経営陣 CTO CxO`
4. `{company} 組織 カルチャー 働き方`
5. `{company} 競合 比較 シェア`
6. `{company} 強み 差別化 特許 技術`

**収集する情報:**
- 直近の売上高・営業利益・成長率（上場企業はIRから）
- 資金調達履歴・累計調達額・直近ラウンド（未上場の場合）
- CEO/CTO等の経歴・バックグラウンド
- 組織規模・エンジニア比率・開発体制
- 主要競合3〜5社とポジショニングの違い
- 技術的優位性・特許・独自アルゴリズム等

#### Agent 3: 動態・リスク・戦略評価（4次元）

担当: 最新ニュース / 採用動向 / リスク / SWOT分析

**実行するWebSearchクエリ（最低6クエリ）:**
1. `{company} ニュース 最新 2025 2026`
2. `{company} 採用 求人 エンジニア 募集`
3. `{company} 技術スタック 開発環境 テックブログ`
4. `{company} リスク 課題 訴訟 不祥事`
5. `{company} 戦略 中期計画 展望`
6. `{company} 口コミ 評判 OpenWork Glassdoor`

**収集する情報:**
- 直近6ヶ月の主要ニュース・プレスリリース
- 現在の採用ポジション・技術スタック・年収レンジ
- テックブログやエンジニア発信の内容
- 事業リスク・規制リスク・競争リスク
- SWOT分析の材料（強み・弱み・機会・脅威）

### Phase 2: 統合・品質チェック

3エージェントの結果を統合し、以下を確認する:

1. **情報の整合性**: 矛盾する情報がないか確認。矛盾がある場合は公式ソースを優先
2. **網羅性**: 12次元すべてに十分な情報があるか。不足があれば追加検索
3. **鮮度**: 情報が最新かどうか。古い情報には時点を明記
4. **出典**: 主要な数値データには出典を付記
5. **架空データの排除**: 検索で見つからなかった情報は「情報なし」と明記。推測・捏造は厳禁

### Phase 3: 構造化レポート出力

#### output_format: full（デフォルト）

以下の12セクションで構成されるフルレポートを出力する:

```
## {company} 包括分析レポート

### 1. 企業概要
- 正式社名 / 設立年 / 本社所在地 / 従業員数 / 資本金 / 上場区分
- 事業ドメインの簡潔な説明（1〜2文）

### 2. MVV（ミッション・ビジョン・バリュー）
- ミッション: [原文引用]
- ビジョン: [原文引用]
- バリュー/行動指針: [原文引用または要約]

### 3. 事業内容・プロダクト
- 主要プロダクト/サービスごとに:
  - サービス名・概要・対象顧客・収益モデル

### 4. 市場環境
- 属する市場のTAM/SAM（可能な範囲）
- 市場成長率・主要トレンド
- 業界の構造変化・規制動向

### 5. 財務状況
- [上場] 直近の売上高・営業利益・成長率・時価総額
- [未上場] 資金調達履歴・累計調達額・直近ラウンド・推定評価額

### 6. 経営陣・組織
- CEO/CTO等の主要経営陣の経歴
- 組織規模・エンジニア比率・開発体制
- カルチャー・働き方の特徴

### 7. 3C分析
- Customer（顧客）: ターゲット顧客セグメント・課題・ニーズ
- Competitor（競合）: 主要競合3〜5社の名称とポジショニング比較
- Company（自社）: 競合との差別化ポイント

### 8. 強み・差別化要因
- 技術的優位性（特許・独自技術・AIモデル等）
- ビジネスモデル上の優位性（ネットワーク効果・スイッチングコスト等）
- 人材・組織面の優位性

### 9. 最新ニュース・動向
- 直近6ヶ月の主要ニュース（日付付き、3〜5件）
- 新規事業・提携・M&A情報

### 10. 採用動向・技術スタック
- 現在の主要採用ポジション
- 技術スタック（言語/FW/インフラ/ツール）
- エンジニア文化（テックブログ・OSS・勉強会等）

### 11. リスク要因
- 事業リスク（競争激化・技術陳腐化等）
- 財務リスク（収益性・資金繰り等）
- 規制・法務リスク
- レピュテーションリスク

### 12. SWOT分析
| | プラス要因 | マイナス要因 |
|---|---|---|
| 内部環境 | **強み(S)**: ... | **弱み(W)**: ... |
| 外部環境 | **機会(O)**: ... | **脅威(T)**: ... |

---
**分析日時**: YYYY年MM月DD日
**情報ソース**: [主要な出典をリスト]
```

#### output_format: summary

12次元を各2〜3行に圧縮した要約版。見出しと箇条書きのみ。
SWOT分析テーブルは必ず含める。

#### output_format: discord

Discord投稿用にMarkdown書式を調整:
- 見出しは `**太字**` で代用（Discordの ## は大きすぎるため）
- テーブルはコードブロックで囲む
- 2000文字を超える場合は複数メッセージに分割
- 各メッセージの末尾に (1/N) 形式のページ番号を付与

## focus引数の処理

focusが指定された場合、該当する次元の情報収集を強化する:

- **財務**: Agent 2のクエリを倍増。IR資料・有価証券報告書を重点的に取得
- **採用**: Agent 3の採用関連クエリを倍増。Green/Wantedly/doda等も検索
- **技術**: Agent 3の技術関連クエリを倍増。テックブログ・GitHub・OSS活動を重点調査
- **競合**: Agent 2の競合関連クエリを倍増。競合各社の詳細比較表を作成

focusが指定されても12次元すべてを出力する（該当次元の深さが増すのみ）。

## 品質チェックリスト（出力前に必ず確認）

- [ ] 12セクションすべてが含まれている（focus指定時も省略不可）
- [ ] 企業名が正式名称で統一されている
- [ ] MVVは公式サイトからの正確な引用である
- [ ] プロダクト名が具体的に記載されている（「各種サービス」等の曖昧表現はNG）
- [ ] 財務数値に出典または時点が明記されている
- [ ] 経営陣の情報が実在する人物のものである
- [ ] 競合分析に具体的な企業名が3社以上含まれている
- [ ] SWOT分析の各象限に2つ以上の項目がある
- [ ] 最新ニュースに日付が付記されている
- [ ] 技術スタックが具体的である（「モダンな技術」等はNG）
- [ ] リスク要因が具体的で企業固有のものである（一般論はNG）
- [ ] 架空のデータが一切含まれていない
- [ ] 「情報なし」の項目が明示されている（空欄や省略ではなく）
- [ ] 分析日時が記載されている
- [ ] すべて日本語で記載されている
- [ ] output_formatに応じた適切な書式になっている

## 注意事項

- 3エージェントは必ず**並列**で起動し、効率的に情報収集する
- WebSearchで情報が不足する場合、WebFetchで公式サイト・IR資料を直接取得する
- 上場企業と未上場企業で財務セクションのアプローチを変える
- 検索クエリの年号は実行時の年に合わせる
- 情報の鮮度を重視し、古い情報には必ず時点を明記する
- 推測や架空のデータは絶対に記載しない。見つからない情報は「公開情報なし」と明記
